# 模板（复制即用）

所有模板都写成 Markdown，放进 `.gameworkflow/`。不要改标题层级，`check_gates.py` 依赖这些标题。

---

## 1. 冻结卡（每个模块一张，≤200 字）

文件：`.gameworkflow/gates/<模块>.md`

```markdown
# 闸门卡 · N 叙事

- 模块：N 叙事
- 顺序预设：叙事驱动
- 日期：2026-11-13
- 负责人：<名字>

## 已定
- 主角动机是"找回妹妹"，不是"拯救世界"
- 主线三章，结局两个（留下/离开）
- 信息投放：第 1 章只让玩家知道"妹妹失踪"

## 待定
- [ ] 第二个结局是否需要独立场景（决定时间：美术冻结前）

## 风险
- 分支量可能超预算：目前估计多 1.5 周

## 下一步验证
- 写一段 10 分钟文字小样，找 2 个陌生人读，看能否复述动机

## 签字
- A 级：<主创>
- B/C 级记录：见 decisions.md 第 12 行
```

校验规则：五个二级标题必须存在且非空；`已定` 至少 3 条；`待定` 每条要写"何时定"；`签字` 必须有 A 级。

## 2. 变更单（改已冻结的东西时）

文件：`.gameworkflow/changes/<日期>-<模块>.md`

```markdown
# 变更单 · 把结局从 2 个改成 1 个

- 改什么：删掉"离开"结局
- 为什么：分支成本超预算 2 周，且第二个结局没有独立机制
- 影响哪几步：N（叙事）、L（最终关卡）、V（小样时长）
- 要重做的最小范围：节拍表最后一章、结局演出
- 风险：玩家重玩动机下降，需要在别处补
- 需要谁同意：A 级（主创）
```

规则：先写变更单，再动手；不许"先改后补"。

## 3. 状态文件（`.gameworkflow/state.md`）

```markdown
# 项目状态

- 项目：<一句话>
- 类型：恐怖联机 / 消消乐 / 叙事冒险 …
- 人数：1
- 每周投入：20 小时
- 顺序预设：叙事驱动
- 当前模块：N 叙事
- 上一个冻结：G0（2026-11-12）
- 下一个待定问题：结局要 2 个还是 3 个？
- 下次外部测试：2026-11-27（目标 3 人）
- 备注：故事由用户自己写，AI 不代笔
```

每完成一个模块就更新这四行：当前模块、上一个冻结、下一个待定问题、下次测试。

## 4. A 级决策流水（`.gameworkflow/decisions.md`）

```markdown
| 日期 | 模块 | 决策 | 理由 | 谁定的 |
|---|---|---|---|---|
| 11-12 | G0 | 只做 4 人合作，不做单人 | 联机是差异点，单人成本更高 | 主创 |
| 11-13 | N | 结局 2 个 | 与预算匹配 | 主创 |
```

只记 A 级；B 级在冻结卡里一句话带过；C 级不记，每周抽查。

## 5. 周复盘（每周 30 分钟）

```markdown
# 周复盘 · W12

- 本周推进：N 叙事（未冻结）
- 卡在哪：结局数量与预算冲突
- 双视角里最刺的一条：挑剔玩家会在第二章跳过对话
- 下周只做三件事：1) 砍一个结局 2) 写 10 分钟文字小样 3) 找 2 人读
- 需要谁拍板：主创（结局）
```

## 6. 玩家测试记录（每两周一次）

```markdown
# 测试记录 · 2026-11-27 · 3 人

- 测什么：能不能在 60 秒内找到第一个目标
- 成功标准：3 人里至少 2 人不用问就找到
- 结果：2/3 找到；1 人在走廊来回走了 40 秒
- 观察到的犹豫点：门口没有视觉引导
- 玩家原话（不要转述成结论）："我以为那扇门是锁的"
- 只改三件事：门口加灯、地面加脚印、门把手高亮
- 下次复测：只验这三件
```

规则：不写"玩家觉得好玩/不好玩"；写行为、原话、秒数。
